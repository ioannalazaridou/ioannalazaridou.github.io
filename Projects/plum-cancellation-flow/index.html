Discovery & Research

The Problem

A one-line "are you sure?" prompt gave no value context, no alternative to leaving, and no way to capture why. Internal data pointed to two solvable causes: cost and underused features.

Why This Matters

Fintech benchmarks show optimised cancellation flows cut successful cancellations by 10–15%. Using static, tier-wide value stats instead of live calculations keeps it a high-impact, low-engineering-lift build.

How might we help users make informed decisions about their subscription by clearly showing the value they're receiving and offering flexible alternatives, so they don't cancel impulsively due to lack of awareness or cost concerns?

Insight

An unoptimised cancellation flow is causing preventable churn and lost revenue.

Problem

How might we surface real value and flexible alternatives, so users don't cancel impulsively?

Hypothesis

Value reminders, downgrade offers, and feedback collection will cut cancellations by 10–15% and turn every exit into product data.

Scoping the Problem Space

Before any screens, I aligned engineering, product, and commercial teams on one document: context, success metrics, user needs, and business goals.

Background

No optimised cancellation flow exists, users can cancel directly without understanding what they'd lose or seeing alternatives. Graceful flows industry-wide cut successful cancellations by 10–15% through soft off-ramps like downgrades and pauses.

Objective

Deflect cancellations with tier-specific value reminders and targeted alternatives, while gathering clean churn data, using static tier averages instead of personalised calculations to keep engineering lift low.

User Goals

  • Value clarity, see what they're actually getting
  • Cost flexibility, downgrade instead of losing everything
  • Trust, a transparent process, no dark patterns

Business Goals

  • Reduce churn 10–15% via value reminders and downgrades
  • Structured feedback to prioritise the roadmap
  • Maintain brand trust with no manipulative UX
  • Low engineering complexity, static over personalised data

User Personas

Three personas, three different reasons for arriving at this screen:

The Cost-Conscious User

Pro/Ultra · tight budget

  • Wants to know if it's worth the cost
  • Feels the price is steep, fears losing everything
  • Needs: a value reminder + a cheaper tier option

The Feature Non-User

Premium/Max · subscribed, not using it

  • Wants to save passively, without thinking about it
  • Forgot they even have premium perks
  • Needs: a tier-specific value reminder + downgrade that keeps the essentials

The Trust-Focused User

Any tier · values transparency

  • Wants to decide without pressure or tricks
  • Hates dark patterns and hard-to-find cancel buttons
  • Needs: an honest flow with a clear, easy-to-find exit

Competitor Analysis

I audited cancellation flows across seven category leaders, Netflix, Revolut, Monzo, ClassPass, Foodpanda, Stake, and Coinbase, for patterns to adopt, adapt, or avoid.

Patterns for Plum

What Works

  • Value reminder, tier-specific stats, Revolut-style
  • A real downgrade path, not just cancel-or-nothing
  • Transparency on exactly what happens and when
  • A post-cancel undo button as a safety net

What To Avoid

  • Too many screens
  • No retention attempt at all
  • Repeating the same message multiple times

Design & Strategy

Four screens, four goals: value reminder → soft alternative → feedback → clean exit. One UI, two tier-based content variants.

User Flow

I mapped every branch, Keep, Downgrade, Confirm Cancel, so both tier variants share one structure instead of splitting into two flows.
